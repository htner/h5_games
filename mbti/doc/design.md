## 1. 项目概述

### 1.1 产品定位

一款嵌入语音房的轻量 H5 互动插件，以 MBTI 四维性格理论为内核，通过"猜主播 / 猜麦上嘉宾"的博弈玩法，将心理测试转化为社交货币。

### 1.2 核心目标

| 目标 | 关键指标 | 说明 |
|------|---------|------|
| 破冰 | 新用户首次互动率 ≥ 60% | 零门槛参与，不需要开麦、不需要打字，点选即完成 |
| 促活 | 单局平均停留时长 ≥ 8 min | 通过悬念节奏（投票→盲填→揭晓）形成连续追看 |
| 变现 | 每局礼物流水提升 15%+ | "题目竞选"和"深度报告"双驱动 |
| 传播 | 结算卡片分享率 ≥ 20% | 性格标签 + 契合度排名自带社交话题 |

### 1.3 目标用户

- **主播 / 麦上嘉宾**：游戏的"被猜者"，是内容产出的核心
- **活跃用户（老粉）**：通过高命中率展示自己"懂主播"
- **路人 / 新用户**：低门槛围观参与，快速融入房间氛围

## 2. 角色定义

| 角色 | 身份 | 权限 |
|------|------|------|
| 发起者 (Host) | 房主或管理员 | 选择卡包、开始/结束游戏、切换被猜者 |
| 被猜者 (Target) | 主播 / 麦上嘉宾 | 提交自己的真实答案 |

> 能不能，一局游戏中 **被猜者可以轮换**，例如先猜主播 5 题，再猜某位嘉宾 5 题，最后合并结算？ 不能

## 3. 完整游戏流程

### 3.0 前置：入口与引导

```
用户视角：
┌──────────────────────────────────────┐
│  房间公屏弹出横幅通知                    │
│  "🎭 主播发起了【灵魂读心术】，           │
│   点击加入，测测你有多懂 TA！"            │
│              [ 立即加入 ]               │
└──────────────────────────────────────┘
```

- **触发方式**：发起者点击房间工具栏中的"互动游戏"按钮
- **加入方式**：用户点击公屏横幅或底部浮窗均可进入 H5 面板
- **延迟加入**：游戏进行中的用户也可随时加入，从当前题目开始计分

### 3.1 阶段一：选择卡包 (Setup) — 仅发起者操作

**发起者操作流程：**

1. 选择**被猜者**（默认为自己，可指定其他麦上嘉宾）
2. 选择**主题卡包**
3. 设置**题目数量**（5 / 8 / 10 题，默认 8 题）
4. 点击"开始游戏"

**卡包体系：**

| 卡包 | 图标 | 测试维度 | 适用场景 | 题目风格 |
|------|------|---------|---------|---------|
| 心动信号 | ❤️ | E/I + T/F | 情感类直播、CP互动 | 恋爱观、暧昧、择偶 |
| 高能社交 | 🔥 | T/F + J/P | 日常聊天、吐槽 | 处事风格、社交尴尬 |
| 脑洞剧场 | 🧠 | S/N | 综艺感强的房间 | 极端假设、荒岛求生 |
| 深夜独白 | 🌙 | 全维度 | 深夜情感电台 | 内心独白、价值观 |
| 职场生存 | 💼 | T/F + J/P | 职场话题房 | 职场关系、决策风格 |
| 随机混搭 | 🎲 | 随机 | 通用 | 系统从所有卡包随机抽取 |

> 卡包支持后台动态配置，可按节日/热点快速上线限定卡包（如情人节、世界杯）。

### 3.2 阶段二：全民选题 (Voting) — ⏱ 20s

**目的**：让用户决定问什么，增加参与感和"揭秘"期待。

**流程：**

1. 系统从卡包中随机抽出 **3 道候选题**，展示题面（不展示选项）
2. 所有猜测者进行投票，选出最想问的那道题
3. 倒计时结束，**得票最高**的题目胜出

**投票权重机制：**

| 行为 | 权重 |
|------|------|
| 普通投票 | x1 |
| 赠送"放大镜"小礼物后投票 | x10 |
| VIP/贵族用户投票 | x3 |

**界面要素：**

- 三道题目以卡片形式横向排列，点击选择
- 实时票数进度条（不显示具体数字，只显示比例动画）
- 右上角倒计时
- 底部引导文案："你最想揭开 TA 的哪一面？"

**边界处理：**

- 票数相同 → 随机取其一
- 无人投票 → 系统随机选题
- 被猜者不参与投票

### 3.3 阶段三：灵魂盲填 (The Guess) — ⏱ 30s

**目的**：核心博弈环节，被猜者填真实答案，猜测者押注预测。

**双端同步操作：**

```
被猜者端                          猜测者端
┌────────────────┐              ┌────────────────┐
│  [题目展示]      │              │  [题目展示]      │
│                 │              │                 │
│  ○ 选项 A       │              │  ○ 选项 A       │
│  ● 选项 B（已选）│              │  ● 选项 A（已选）│
│  ○ 选项 C       │              │  ○ 选项 B       │
│  ○ 选项 D       │              │  ○ 选项 C       │
│                 │              │  ○ 选项 D       │
│  [ 锁定答案 ✓ ] │              │  [ 确认猜测 ✓ ] │
└────────────────┘              └────────────────┘
```

**关键规则：**

- 被猜者选的是**自己的真实倾向**，该答案加密提交，不会提前泄露
- 猜测者选的是**对被猜者的预测**
- 两端都必须在 30s 内提交；未提交视为弃权
- 被猜者提交后，其状态变为"已锁定"，公屏显示 "🔒 TA 已做出选择..."

**氛围设计：**

- 倒计时最后 10s 时，界面加入心跳动效 + 节奏音效
- 公屏滚动弹幕："全场 XX 人正在猜测中..."
- 被猜者锁定后出现悬念提示："TA 的答案已锁定，你确定不改了吗？"

**押注加码（可选变现点）：**

- 猜测者可额外赠送"信心之星"礼物，表示"我非常确定"
- 猜对时获得双倍积分，猜错不额外扣分

### 3.4 阶段四：答案揭晓 (The Reveal) — 由被猜者/发起者控制节奏

**目的**：制造最大化的悬念和讨论空间，是直播间高潮的核心。

**揭晓流程（单题）：**

```
Step 1  展示猜测分布
        ┌──────────────────────────┐
        │  全场猜测结果：              │
        │  A. ████████░░  62%       │
        │  B. ███░░░░░░░  23%       │
        │  C. █░░░░░░░░░   8%       │
        │  D. █░░░░░░░░░   7%       │
        └──────────────────────────┘
        主播口播："居然这么多人觉得我选 A？"

Step 2  被猜者点击 [ 揭晓答案 ]
        ┌──────────────────────────┐
        │  ✨ TA 的真实答案是：B ✨     │
        │                          │
        │  猜对率：23%               │
        │  "只有少数人真正看穿了 TA！"  │
        └──────────────────────────┘

Step 3  猜对/猜错反馈
        猜对者 → 头像弹出 "看穿你了" 气泡 + 烟花特效
        猜错者 → 头像弹出 "翻车了" 气泡
        公屏 → "恭喜 @用户A @用户B 等 XX 人猜中！"
```

**节奏控制：**

- 揭晓按钮仅被猜者/发起者可见，控制节奏
- 建议每题揭晓后留出 **15-30s** 的讨论时间
- 超过 60s 未点击揭晓 → 系统自动揭晓

**连击机制：**

- 连续猜对 2 题 → 公屏提示 "🔥 @用户A 二连读心！"
- 连续猜对 3 题 → 全屏特效 "⚡ @用户A 三连读心！灵魂共鸣！"
- 连续猜对 5 题 → 超稀有特效 "🌟 @用户A 完美读心！"

### 3.5 阶段五：MBTI 画像生成 (Profile) — 自动

**目的**：根据被猜者的全部真实答案，生成 TA 的 MBTI 倾向画像。

- 如果题目不足以覆盖全部维度，未覆盖的维度标记为"?"（如 EN?P）

## 4. 多轮 / 连续游戏机制

### 4.1 单局结束后

发起者可选择：

1. **换人继续** — 切换被猜者为另一位麦上嘉宾，开启新一局
2. **加赛** — 使用同卡包的剩余题目，继续当前排名累计
3. **结束游戏** — 展示最终排名，回到正常直播

### 4.2 赛季排行榜

- **周榜**：统计用户在所有房间的累计读心积分
- **月榜**：月度排名前 100 名获得全局专属标识
- **主播亲密度排行**：记录用户在特定主播房间的历史契合度

## 6. 状态机与异常处理

### 6.1 游戏状态流转

```
IDLE → SETUP → VOTING → GUESSING → REVEALING → PROFILE → SETTLEMENT
  ↑                                     │
  │              （如果还有下一题）        │
  │              REVEALING → VOTING ─────┘
  │                                      
  └──────────── SETTLEMENT (游戏结束) ───→ IDLE
```

### 6.2 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 被猜者中途离开房间 | 暂停游戏，等待 60s；超时则自动结算已完成题目 |
| 被猜者未在 30s 内提交答案 | 该题作废，跳到下一题；公屏提示"TA 选择了沉默..." |
| 发起者离开 | 权限自动转移给被猜者；被猜者也离开则强制结算 |
| 房间人数降到 0 | 自动终止游戏，不生成排行榜 |
| 网络断线重连 | 用户重连后自动恢复到当前游戏阶段，已提交的答案保留 |
| 中途加入的用户 | 从当前题目开始参与，之前题目不计分 |

### 9.2 运营看板

- **日活指标**：日均开局数、日均参与人数、人均参与局数
- **互动指标**：平均每题猜测人数、平均猜对率、连击率分布
- **变现指标**：游戏场景 ARPU、道具购买转化率、深度报告解锁率
- **传播指标**：分享率、分享回流率、新用户来源占比

## 10. 技术对接要点

### 10.1 JSBridge 接口清单

| 接口 | 方向 | 说明 |
|------|------|------|
| `requestPay(itemId, amount)` | H5 → Native | 唤起 Flutter 支付弹窗 |
| `onAnswerSubmit(questionId, answer)` | H5 → Server | 提交答案（被猜者/猜测者通用） |
| `onVoteSubmit(questionId)` | H5 → Server | 提交投票选择 |
| `triggerNativeEffect(effectType)` | H5 → Native | 触发原生层全屏动效 |
| `getUserInfo()` | H5 → Native | 获取当前用户信息（头像、昵称、VIP等级） |
| `shareCard(imageUrl, text)` | H5 → Native | 调用原生分享面板 |
| `onGameStateChange(state)` | Server → H5 (room_push) | 游戏状态变更推送 |
| `onRevealResult(data)` | Server → H5 (room_push) | 揭晓答案推送 |

### 10.2 通信架构

```

└─────┬────┘                                                 │
      │ JSBridge                                   gRPC/HTTP │
┌─────┴────┐                                           ┌─────┴────┐
│  Flutter  │                                          │ mbti svc  │
│ (Native)  │      room_push (事件推送)                 │  (Go)     │
│           │ ◄─────────────────────────── ┌──────────┐│           │
└──────────┘                               │room_gate-││  MySQL    │
                                           │  way     ││  + Redis  │
                                           └────┬─────┘└──────────┘
                                                │ room_push
                                                │ (mbti svc 发送)
```

### 10.3 性能要求

| 指标 | 目标 |
|------|------|

| H5 首屏加载 | ≤ 1.5s (4G 网络) |
| 内存占用 | ≤ 50MB (低端机适配) |
